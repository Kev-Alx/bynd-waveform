# Learned model directions and source receipts

27 October 2026, Asia/Taipei. This note follows the latest experimental steering: seek the unchanged joint WER/quality gate, transfer/defense preservation and practical computational scalability; consider reusable learned models directly. It is not a publication plan. The next queued/detached GPU script may run for **at most 13 hours**. No GPU work, queue changes, frozen edits, evaluation-target queries or interface edits were performed for this research. The root experiment runner handles the busy GPU and scheduling.

## Actionable conclusion

The best immediate learned-model hypothesis is an **input-conditioned temporal feature-residual policy**, trained on disjoint speech through the already qualified frozen HiFi-GAN and a permitted ASR source. It predicts an edit in one forward pass for each new recording. A trained policy is a different method from optimizing a separate feature delta for every input. Its deployment speed and joint success remain to be measured.

A **learned signal processor acting directly on the original waveform** is a valuable independent fallback: predict smooth time/frequency filter controls, optionally a tightly bounded monotonic time warp, without vocoder reconstruction. This offers a stronger quality-preservation bias and a cheap inference path, but may lack the expressive power to exceed 75% WER because modern recognizers tolerate many such transformations. Test attack signal early rather than assume intelligible transformations will transfer.

A **codec-latent conditional generator** is a credible third family, but replacing the encoder/decoder introduces reconstruction, rate, quantization and compatibility work. It is lower priority for a single 13-hour queue unless a matching implementation/checkpoint passes reconstruction and gradient checks quickly. None of the inspected sources demonstrates our joint gate on this hardware.

## Why the previous U-Net failure does not rule out learned models

The [saved R3 diagnostic](/workspace/improvement/execution48/r3-failure-diagnostics.md) establishes a narrow, important failure: all 24 decoded attacked transcripts equal clean; trained median residual RMS is **1.2389e−6**, using **0.0413%** of the allowed 0.003 RMS. The initial residual was almost entirely DC (**99.9979%** of power). After training, remaining energy is strongly concentrated at boundaries. **99.83%** of logged update gradients exceeded the clipping threshold. Training completed 1,779 updates/7,116 microbatches in 3,541.89 seconds; checkpoints never developed attack signal.

The fixed STFT/content weights were about **65.08/186.61**. Their separate waveform-gradient norms were calibrated at one random small perturbation, not their combined parameter gradients near the learned identity solution. A checkpoint tie in WER then favored smaller STFT error. These observations are compatible with penalty pressure, cross-example cancellation, initialization/upsampling bias, or an inadequate source objective; saved traces do not isolate which caused collapse. Frequent clipping alone does not prove a bug.

The original [R3 implementation](/workspace/improvement/r3_waveform.py) also differentiates through sample-level upsampling using CPU backward/device copies under strict CUDA determinism, and through a frozen WavLM content encoder. These are real training costs. A model predicting lower-rate features or filter controls avoids that exact architecture and may avoid that execution path. Increasing parameter count alone would not repair the measured objective/initialization problems.

The correct lesson is **instrument and test the learned attack signal early**. Record paired clean/attacked NLL and decoded WER, residual norm/budget utilization and spectra, source-versus-quality parameter-gradient norms/cosines, and across-example gradient alignment on a small fixed diagnostic schedule. A nonzero output, lower training loss and an actual decoded attack are different events. Use 48 points for every performance pilot.

## Ranked implementable experiments

### 1. Directly trained temporal feature policy: highest immediate executability

**Model:** take clean cached WavLM6 features at their native frame rate; use an input normalization inside the policy, a 128–256-channel temporal network with dilated residual/depthwise or GLU blocks, and a same-shape feature-residual head. Measure the actual parameter count rather than claim a size in advance. Preserve the decoder's original unnormalized feature contract. Use a tiny random head with zero bias, a maximum-radius projection and an exact identity control; do not impose a nonzero minimum edit that would manufacture distortion. Native feature rate is far below the 16 kHz waveform rate.

**Training:** begin on the existing disjoint one-hour training manifest, caching clean features once. Frozen HiFi-GAN renders the model's features; permitted source ASR input gradients update policy weights. This is training across recordings, not a new per-recording deployment optimizer. Full-utterance transcripts must match the audio; arbitrary crops cannot inherit whole-utterance text. Start with one permitted source to measure attack learning, then use a fixed registered source/transform schedule if the initial signal supports it. A second source is an additional cost, not a free transfer guarantee.

**Specific hypothesis:** the previous collapse partly reflects sample-level architecture plus identity-favoring training; a temporally contextual feature policy can learn shared nonzero acoustic edits while staying near the qualified decoder's reconstruction. Use a short registered attack-learning warmup, then introduce a fixed reference distortion schedule, rather than immediately transplanting both large R3 coefficients. Freeze that schedule before the full performance pilot. Bounded/normalized lexical objectives are optional named variants; changing the loss silently would obscure the cause.

**Necessary controls:** same policy with constant/shuffled input to detect an accidental UAP; frozen identity and original quality FV50; original strong FV50 as an attack-positive/quality-negative control; initial/untrained policy; policy attack learning without versus with the declared quality schedule if the budget supports an ablation. No direct MOS-predictor maximization. Compare saved per-recording quality and attack outcomes, not training NLL alone.

**Feasibility:** likely to fit the 24 GB card with frozen small source, batch one/accumulation and no large-v2; this is an architectural estimate, not a memory benchmark. Reusing clean feature caches removes repeated encoding during training, but **new-audio inference must charge WavLM encoding + policy + vocoder**. Training still pays source/vocoder backwards and may need checkpointing. Benchmark full shortest/median/longest exposed inputs before choosing updates or promising a training duration.

**Stop/fallback:** if a short, registered first learning window produces neither meaningful paired source-loss gain nor nontrivial decoded change on the full 48-point pilot, save the negative checkpoint and stop extending it. A supervised fit to a few exposed attack residuals may diagnose capacity, but does not establish generalization. If a model learns strong attacks while UTMOS fails, do not distill that failure and call it quality preservation. Switch to the independent waveform-processor hypothesis or a separately justified objective change. Direct training does **not** require a successful teacher; only claims of distilling qualified behavior do.

### 2. Learned waveform signal processor: independent quality/efficiency hypothesis

**Model:** a small temporal controller reads the original waveform's STFT/features and predicts smoothly bounded multiband gains or short FIR controls; apply them to the original signal with differentiable STFT/iSTFT or convolution. Optionally test a separate monotonic time-warp head with fixed endpoints and bounded local rate. Smoothness, gain/rate bounds and output duration must be frozen. Prefer a small interpretable control space over reconstructing speech from scratch.

**Hypothesis:** direct controlled filtering retains natural phase/timing/content better than unrestricted feature resynthesis, while an input-conditioned controller learns shared ASR weaknesses and amortizes generation. DDSP/DENT-DDSP [10,11] establish components; EvilHarmony [8] establishes attack relevance of structured spectral filtering. Neither establishes this result.

**Critical failure modes:** mild EQ/rate changes may be in the recognizer's augmentation invariances, giving high quality and little WER; stronger changes may erase consonants or alter words. An invertible/monotonic warp does not prove human intelligibility. Warps implemented with CUDA interpolation/grid sampling can hit deterministic-backward restrictions; qualify their actual gradients and runtime before training. Do not repeat R3's uncharged CPU-copy workaround or weaken backend rules silently.

**Feasibility:** potentially cheaper and smaller than a learned vocoder path; source gradients likely dominate training. It needs no attack-teacher corpus and can use existing one-hour audio. Implement one operator first, validate an identity round trip, then a fixed 48-point model pilot. Stop if no attack signal emerges at the registered quality-preserving bounds; expanding those bounds is a new hypothesis, not an excuse to consume the remaining 13 hours.

### 3. Conditional codec-latent residual model: plausible but more setup risk

Use a released native-16-kHz codec/decoder already identified in the earlier notes, qualify no-edit reconstruction on all 48, and train an input-conditioned latent head. Keep semantic/codebook choices explicit. A continuous edit after quantization can leave the codec's valid token set; it is not automatically a discrete-token attack or robust to a later independent codec defense. A straight-through gradient is an approximation needing checks.

This family differs from a universal latent tensor [2] and from changing to a larger vocoder alone. Prefer it only if reconstruction, gradient/memory fit and implementation are ready within the short setup allowance. Otherwise preserve the source idea and use the existing qualified HiFi-GAN path for this queue. Do not spend the full budget downloading/debugging a new pretrained model. A diffusion chain is lower priority because multiple synthesis steps/backpropagation add cost and no local evidence predicts a better joint frontier.

## What a 13-hour queue should establish

A **13-hour ceiling is a maximum budget, not a forecast or a guaranteed success deadline**. Root should register one primary model and at most one scientifically justified fallback, with phase deadlines and explicit normal scientific stops. An illustrative allocation is 0.5 h setup/preprocessing/profile, 1 h first learning plus 48-point signal screen, 5 h continued training only if warranted, 1 h complete pilot/controls and audit, 0.5 h conditional exposed validation, 2 h conditional transfer/defenses, 1 h remaining accounting/reporting, and 2 h contingency. Replace allocations with measured forecasts before launch; all stages and contingency must fit the same ceiling. Do not silently give every phase 13 hours or restart an expired script under a new timer.

**Forecast from the new method.** R3 previously managed about 2.01 microbatches/s, but that includes its different penalties, encoder, lengths and transfers. Strong FV50 took about 19.61 s/clip for 50 updates in the historical queue, but that is not a learned-policy training benchmark. Neither can be imported as an exact training rate. Measure the proposed full training update, cache creation and generation path, then compute `expected_updates × measured_seconds/update + preprocessing + scheduled full-cohort evaluation`. Save measured variability, GPU allocation hours, CUDA-event elapsed time, wall time and peak allocated/reserved memory. If conditional evaluation does not fit, preserve partial receipts and report that limit rather than claim the full goal.

**Training/data costs remain visible.** Teacher generation is zero for direct source training; cache/preprocessing is not zero. If an optional teacher/student route is chosen later, use the relevant teacher's measured throughput and include target generation plus training in break-even. A one-forward policy does not make these sunk costs disappear. Report new-audio latency both with and without a pre-existing feature cache. Test complete 48-point per-recording mean/median/p95 and seconds/audio-second, including I/O consistently, on the actual card.

**Selection stays strict.** Full-cohort source WER >75%, DNSMOS ≥3, NISQA ≥3.75 and UTMOS ≥3.5 must hold; then freeze the model/checkpoint before the registered validation, unseen recognizers and defense recipes. New models do not inherit transfer/defense resistance from their teacher or representation. Keep source conditions and reserved targets separate. Measure post-defense clean quality too. Blinded human original-word recovery remains necessary before claiming content preservation. A useful proposed deployment-efficiency signal is a tenfold reduction in measured generation time versus the matched per-recording search, with complete training-cost break-even at explicitly stated workloads. This is a research target, not a user-specified latency limit.
